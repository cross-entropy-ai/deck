## 总体判断

当前架构方向是对的：`Action -> apply_action() -> SideEffect -> App 执行副作用` 已经把不少交互逻辑从 TUI 主循环里拆出来，`RefreshWorker` 也把慢 IO 从 UI loop 移走了。但实现还没有真正“分层稳定”：`AppState` 过大，`app` 层仍直接改状态和执行 tmux/PTY/配置副作用，`infra` 的错误普遍被吞掉，导致用户看不到失败，测试也很难覆盖真实边界。

## 2. Rust 习惯用法

### [Major] 启动时配置解析失败会静默回默认值，并可能覆盖用户配置

锚点：`src/model/config.rs:106`



问题：如果 `config.json` 有语法错误，`load()` 返回 default。随后 `ensure_complete()` 很可能插入默认 keybindings，`cfg.save()` 会把默认配置写回去。用户的坏 JSON 不只是被忽略，还有被覆盖的风险。

## Top 5 改进建议（按 ROI）

1. 修复配置加载/保存错误处理：启动改用 strict parse，`Config::save()` 返回 `Result`，tmux/config 失败进入 UI 错误状态。优先级最高，因为它能避免用户配置被覆盖和操作静默失败。
